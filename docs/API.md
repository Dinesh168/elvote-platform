# API reference

**Server:** Node.js + Express 4 in [`backend/`](../backend). Routes are in `backend/src/routes/controllers/{users,voters,constituency,private}.js`, and auth and routing in `backend/src/routes/middleware/RouteMap.js`. All 38 endpoints the client calls exist on the server; the 1:1 match was verified on 2026-11-17. The OpenAPI UI is served at `/swagger-docs`, generated by swagger-autogen into `swagger-output.json`, which is gitignored.

When you add an endpoint: add the route in `backend/`, the service method in the client `services/`, and a row here.

## Conventions

| | |
|---|---|
| Base path | `/api` (`BASE_ROUTE` in `schemaConstants.js`) |
| Auth | Header `token: <Firebase ID token>`, verified with `firebase-admin` `verifyIdToken` (project `elvote-aeb0e`). Every `/api/*` route requires it |
| Scope | Header `x-constituency: <constituency_number>`, used to pick the `voters_<C>` / `data_collection_<C>_<A>` tables. ⚠ Not validated against the caller's account (see PRODUCTION_READINESS B3) |
| Optional | Header `x-filters: <JSON>`, parsed into `res.locals.filters` (the client doesn't send it) |
| Identity | Middleware loads the `users` row by Firebase UID into `res.locals` (`id, role, account_id, polling_station_id, …`). Controllers trust only this, not the body, for the caller's identity |
| Body | JSON, snake_case; most reads are **POST** with `{ filters }` |
| Paging | `page_num` (1-based), **50 rows per page** |
| Timing | Response header `X-Server-Start-Time` (and `X-Server-End-Time` in non-production CORS config) |
| CORS | Any origin, `credentials: true` |
| Limits | JSON and upload bodies up to 100 MB |

### Error contract

Errors return `{ status, message, errorName, extras }`, with the same code as the HTTP status (`backend/src/errorhandlers/`):

| `status` | Error class | Client behaviour |
|---|---|---|
| `400` | InvalidRequestError | Logged |
| `401` | AuthenticationError (missing or invalid token) | `signOut()` + `AsyncStorage.clear()`; the request resolves `undefined` |
| `403` | AccessPermissionError (e.g. non-super-admin on `private/*`) | Logged |
| `409` | FeatureRestrictionError | Logged |
| `410` | UserNotExistError: no `users` row for this UID | *Fill Profile* screen |
| `411` | UserRequestPendingError | *Pending Approval* |
| `412` | UserRequestRejectedError | *Rejected* |
| `413` | UserPermissionNullError: `permissions_list` empty | *No Permissions* |
| `414` | InvalidInputError (e.g. "Pass Key is invalid") | Logged |
| `500` | DatabaseError / UnexpectedLogicalError | Logged |

`POST users/mine` (profile creation) is exempt from the 410–413 gate.

### The `filters` object

Most voter and user endpoints accept `filters`. Keys come from `FILTERS_LIST` in `constant.js`, plus `sno` and `is_voter_voted` from `INITIAL_FILTER_SORT`. See [DATA_MODEL.md § Filters](DATA_MODEL.md#filters) for types and semantics. Unset filters are `null` or omitted.

`POST users/mine` **upserts** the caller (by Firebase UID) as `role=volunteer`, `permissions_list={"1":"1"}`, in the account whose `pass_key` matches. New rows default to `pending`. Validation: name required, mobile ≥ 10 chars, valid pass key, otherwise 414 with per-field messages in `extras`. ⚠ It bypasses the approval gate, so an existing user can re-post it to change account or reset an admin to volunteer (PRODUCTION_READINESS B5).

`User` list item *(inferred)*: `id, unique_id, name, role, mobile, polling_station_id, polling_station_name, polling_station_part_no | part_no`.

## `private/*`: `services/PrivateDataService.js` (super-admin)

The server enforces super-admin with `validatePrivateUser(userId)` in `private.js`, which compares against the same hard-coded Firebase UID as the client's `PRIVATE_USER_ID` and returns 403 otherwise. Every call except `create_constituency` also needs a valid account `pass_key` (414 if invalid).

| Method | Path | Body | Notes |
|---|---|---|---|
| POST | `private/create_constituency` | `{ constituency_name, constituency_number }` | Upserts `constituency`; **creates table `voters_<C>`** |
| POST | `private/create_account` | `{ account_name, constituency_number_id, pass_key }` | Creates the party account + mapping; **creates `data_collection_<C>_<A>`, `live_voting_<C>_<A>`, `polling_station_for_party_<C>_<A>`** |
| POST | `private/create_admin_user` | `{ email, pass_key }` | Upserts a user by email with `role=admin`, `approved`, attached to the pass key's account |
| POST | `private/upload_voters_data` | multipart: `file` (XLSX), `pass_key` | Imports the roll: polling stations, booth strength, voters (dedupe on EPIC), optional pre-collected canvassing. Column order in [DATA_MODEL.md § 5](DATA_MODEL.md#5-voter-xlsx-import-format-post-privateupload_voters_data) |
| POST | `private/clear_voters_data` | `{ pass_key }` | **Destructive.** Exports canvassing to `sheets/data_collection_<C>_<A>.xlsx`, then **TRUNCATEs** `voters_<C>` (shared by all parties in that constituency) and `data_collection_<C>_<A>` |

### Parties by state (spec party-states)
- `GET /v1/catalog/parties?state=XX` → national parties (no states set) + parties of XX; no `state` → all.
- `GET /v1/admin/parties` → adds `states: string[]` ([] = national).
- `PUT /v1/admin/parties/:id/states { states: string[] }` (super-admin; [] = national; unknown state 422 `state_unknown`). Approving a request with `newPartyName` links the new party to the request state.

### Polling day: find any voter of the assembly (spec flow-fixes P1/P2)
- `GET /v1/m/:mid/polling/find?epic=XXX` or `?part=101&sno=5` → `{ items: [{ id, sno, part, boothName, name, nameLocal, relation, relative, age, gender, voted, own }] }` (no group/phone). 422 without EPIC or booth + S.No.
- `POST /v1/m/:mid/voters/:id/changes` with only `votedAt` is accepted for any booth of the assembly while the election window is open; other changes stay limited to own booths (403 `booth_forbidden`).

### Admin views + super-admin team control (spec admin-views)
- `GET /v1/m/:mid/polling/find?q=` — one box: digits = S.No in every booth, letters+digits = EPIC, text = name; first 50. At most 30 searches a minute per person → 429 `find_rate` (spec security-fixes SF2).
- `GET /v1/m/:mid/booth-table` adds `area`, `village`. Memberships in `/v1/me` carry `views` (zone/area/village).
- Super-admin: `GET /v1/admin/customers/:id/members`; `POST /v1/admin/volunteers {mobile|email, name, partyAcId, booths}`; `PUT /v1/admin/customers/:id/members/:mid/booths {booths}`; `DELETE /v1/admin/customers/:id/members/:mid`; `PATCH /v1/admin/booths/:state/:ac/:no/place {area?, village?}`; `PATCH /v1/admin/customers/:id {views}`.
